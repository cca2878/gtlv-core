# 匹配与坐标输出：算法契约（各壳自实现）

core 只做推理，产物是 [`types::DetectResult`]（检测框 + 特征向量）。从这里到「点哪几个格、按什么顺序」
是**纯数学后处理**——欧氏距离 + 矩形最优指派，不依赖推理引擎、不涉及跨语言边界。故 core **不提供**该 API，
**各消费壳按自己语言的惯用法各自实现**；本文是它们必须遵守的契约。

参考实现：`gtlv-go` 的 `internal/matcher/assignment.go`（Go）。

## 输入

来自 `DetectResult`：

| 名称 | 含义 |
|---|---|
| `detections` | 检测框；`class_id == 0` 为答案格（**已 NMS + Top-K 过滤**），`class_id == 1` 为提示框 |
| `answer_features` | 各答案格的 512-d 特征，**与 `class_id == 0` 的检测框一一对应、同序** |
| `prompt_features` | 提示词按 k 段等分后各段的特征，**按左→右顺序**；`k = prompt_features.len()` |
| `prompt_box` | 提示框（class 1 中置信度最高者） |

记 **m = 答案格数**，**k = 提示字数**（由 core 用提示框长宽比标定，见下）。

## 前置校验（缺一不可）

按顺序检查，任一不满足即判定本图不可解、应换图重试：

1. `prompt_box` 存在，否则 → `no prompt box`。
2. `m > 0`，否则 → `no answer boxes`。
3. **`2 ≤ k ≤ 4`**，否则 → k 超范围（提示框缺失/异常，或提示段特征提取失败被 core 全或无清空）。
4. **`m ≥ k`**，否则 → 检测漏了目标（答案格数不足以覆盖 k 个目标）。
5. `answer_features.len() == m`（core 对特征提取失败的框会静默跳过，须校验对齐）。

> **k 的来源**：core 按提示框长宽比 `aspect = 宽/高` 标定字数——`aspect < 1.95 → 2`，`< 2.60 → 3`，否则 `4`。
> **绝不能用 m 推断 k**：gt 新格式的答案网格含干扰字，m 常 > k（现观测 k+1）。这是当年的致命 bug 点。

## 核心：矩形最优指派

把 **k 个提示特征（行）** 指派到 **m 个答案特征（列）**，要求：

- **单射**：每行占一个**互不相同**的列（k ≤ m）；
- **最小化总代价**：代价 = 行特征与列特征的**欧氏距离**；
- 未被指派的 `m − k` 列即**干扰字，直接丢弃**。

```
cost[i][j] = ‖prompt_features[i] − answer_features[j]‖₂        (i < k, j < m)
求 injective f: {0..k) → {0..m)  使 Σ cost[i][f(i)] 最小
```

**必须是矩形单射，不能是方阵双射**：方阵双射会强制点满全部 m 个格，无法排除干扰字。

**实现方式**：k ∈ {2,3,4} 且 m 很小（core 侧上限 `MAX_ANS = 8`），**穷举单射 + 最优值剪枝**即可
（最坏 8·7·6·5 = 1680 次，纳秒级）。无需匈牙利算法。剪枝：递归中若累计代价 `≥` 当前最优则立即回溯。

维度不等的两个特征向量，其距离取 `+∞`（视为不可匹配）。

## 输出：点击坐标与顺序

对每个提示段 `i`（按 **i 递增** 输出，即提示词左→右序 = **点击提交顺序**）：

- 取所选答案框 `f(i)` 的**中心点** `((x_min+x_max)/2, (y_min+y_max)/2)` 作为点击坐标；
- 置信度（可选，用于诊断/路由）：`conf = 1 / (1 + dist)`，`dist = cost[i][f(i)]`。

**顺序即正确性的一部分**：gt 校验点击顺序，乱序 = 验证失败。

> 提示框按 k 等分得到的各段矩形（`x_min + i·segWidth` ~ `+ (i+1)·segWidth`，y 沿用提示框）仅用于
> 展示/回映，不参与指派。

## 已知残差（供实现者理解边界）

即使指派正确，端到端仍有约 10% 失败，构成（实测 n=300）：`m=k` 类 63%（漏目标或排序错）、
`m>k` 匹配错 28%、检测类 9%。这些是模型能力问题，**不是本算法的问题**——实现忠实即可，不必"优化"指派。
