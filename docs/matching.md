# 匹配契约：由推理结果计算点击坐标

`gtlv-core` 的输出止于 [`types::DetectResult`]，即检测框、特征向量与提示词字数 k。将提示词指派至答案格、计算点击坐标及其提交顺序，由调用方实现：该步骤为纯数学计算，不依赖推理引擎，亦不涉及跨语言边界。

本文档规定该实现须满足的规格。遵循本规格的不同语言实现将产生一致的点击顺序。

## 输入

| 字段 | 说明 |
|---|---|
| `detections` | 答案格，已完成 NMS 与数量截断；`bbox` 为原图像素坐标 |
| `answer_features` | 各答案格的 512 维特征，与 `detections` 一一对应且顺序一致 |
| `prompt_features` | 提示词各字的 512 维特征，按自左至右排列 |
| `prompt_box` | 提示词整体框 |

记 m 为 `detections.len()`（答案格数量），k 为 `prompt_features.len()`（提示词字数）。

> k 由提示框长宽比标定，不得由答案格数量推断。答案网格中混有不应点击的干扰字，m 通常大于 k
> （常见为 k+1），据此推断将导致点击错误。`gtlv-core` 已给出 k，调用方应直接采用。

## 前置校验

依次检查以下各项，任一不满足即表明该图像无法求解，应更换图像重试：

1. `prompt_box` 存在
2. m 大于 0
3. k 介于 2 与 4 之间（超出该范围表明提示框异常，或提示词特征提取未完成）
4. m 不小于 k（答案格数量不足以覆盖 k 个目标，表明检测遗漏了目标）
5. `answer_features.len()` 等于 m（特征提取失败的答案格会被跳过，须校验对齐）

## 指派

将 k 个提示词特征指派至 m 个答案格特征，须满足：

- **单射**：各提示词占据互不相同的答案格（k ≤ m）
- **总代价最小**：代价为两特征间的欧氏距离
- 未被选中的 m − k 个答案格即干扰字，予以丢弃

```
cost[i][j] = ‖prompt_features[i] − answer_features[j]‖₂     (i < k, j < m)
求单射 f: {0..k) → {0..m)，使 Σ cost[i][f(i)] 最小
```

指派须为单射而非双射。双射将强制点击全部答案格，无法排除干扰字。

k 至多为 4，m 至多为 8，穷举全部单射并以当前最优值剪枝即可（最坏情形为 8·7·6·5 = 1680 次，耗时在纳秒量级），无需匈牙利算法。两特征维度不等时，距离取正无穷。

### 距离须以 f64 累加

特征为 512 维 f32。以 f32 累加平方和时，舍入误差足以导致选中不同的答案格，即改变输出结果。应将各项提升至 f64 后再行累加与开方；中心点与置信度亦须以 f64 计算。

## 输出

按 i 递增输出，即提示词自左至右的顺序，亦即点击的提交顺序：

- **坐标**：所选答案格的中心点，`((x_min + x_max) / 2, (y_min + y_max) / 2)`
- **置信度**（可选，用于诊断）：`1 / (1 + dist)`，其中 dist 为该次匹配的距离

提交顺序是正确性的组成部分。服务端校验点击顺序，顺序错误即判定失败。

## 实现验证

与已知正确的实现进行比对时，应采用容差而非逐位相等。不同后端（WASM 的 SIMD128 与原生 x86）的矩阵乘内核归约顺序不同，所得特征本身即存在 ulp 量级差异。

建议的判据为：指派结果（所选答案格及其顺序）须完全一致；坐标容差取 1e-3 像素，置信度容差取 1e-5。现有两个实现在真实验证码样本上满足该判据，坐标差异不超过 3.1e-5 像素。

## 已知上限

即便实现完全正确，端到端仍有约 10% 的图像无法通过，成因包括目标漏检、点击顺序错误，以及特征无法区分的混淆字。此为模型能力的边界而非本算法的缺陷，实现应忠于本规格，不必对指派逻辑另作调整；调用方应具备更换图像重试的能力。
